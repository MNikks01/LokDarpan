God's Eye View Borrowing Ledger

What LokDarpan can legitimately take from a real-time surveillance globe, judged against the code LokDarpan actually runs rather than the code its documents describe.

01Executive summary

The short answer. Keep MapLibre, PMTiles and PostGIS as they are. God's Eye View (GEV) is worth studying for eight engineering mechanisms, not for its renderer, its data or its look. And LokDarpan has three foundations to fix before any borrowed idea can pay off.

Four facts that reorder the plan

These come from reading the implementation. Each contradicts what the documentation suggests.

Finding ANo map API carries a real datasetVersion

All 11 explorer, geo, tender, search and document-list route handlers return a hard-coded datasetVersion: 0, even though admin_unit_boundary.dataset_version_id exists. meta.asOf is the time of the response (respond.ts:19), not the data vintage. Every route is force-dynamic; the documented cache-tag ISR is not implemented. A version in a share link would pin nothing today.

Finding BThere is no point layer to budget

The explorer draws state outlines, child boundaries, a selected unit and a tender choropleth. The 400-feature cap exists only in a mobile wireframe. ADR-022's "works above districts" hit order and 20 px road hit layer are no longer in MapCanvas.tsx. Tenders are deliberately not pins, because the portals publish no coordinates.

Finding CIngestion downloads are unbounded

CAG, LGD and BEAMS read whole bodies with arrayBuffer(); GePNIC and Overpass use text(). None has a size cap, and only the OCR client has a timeout. CAG downloads the entire body before checking that it is a PDF.

Finding DArchitecture rules are prose, not checks

ESLint enforces type safety and bans parseFloat; the neutrality CLI scans vocabulary. Nothing enforces import direction. The ServerText brand exists in packages/neutrality, but no web component uses it, and tenders.tsx alone writes about fifteen reader-facing sentences inline.

What never comes across

CesiumJS, Google Photorealistic 3D Tiles, Esri imagery, every live-tracking layer (aircraft, ships, satellites, transit), CCTV, licence-plate readers, military installations, sensor shaders, the HUD aesthetic, the voice agent, motion interpolation, and GEV's proximity-based "hand off to the nearest camera". Section 11 gives the reason for each. The common thread: GEV's value is watching; LokDarpan's is citing.

One sequencing rule

Wire the real datasetVersion and the data-state contract through before building a layer registry, share-link pinning or request coalescing. All three are keyed on the version, and each would otherwise be built twice.

Decisions already right, which must not be disturbed

  • No invented points. Tenders shade the issuing office's district; local bodies show a labelled extent, never a fabricated polygon. This is stronger than anything in GEV.
  • Omit, never zero. withTenderCounts leaves the property off, so the ["has","tenderCount"] filter cannot shade a false zero.
  • Spatial work in PostGIS. The repository's own rule, that containment is milliseconds in the database and a frozen tab in JavaScript, is correct.
  • Selection in the URL, camera derived from it. One canonical /units/:id; the explorer is a view, not a second naming scheme.
  • Self-hosted basemap. No map vendor logs the reader.
  • Coverage is a first-class record, never inferred from a list's length.
  • ingestion_run sits outside the load transaction, so a failure survives rollback.
  • The rail is the accessible equivalent of the map. Labels are aria-hidden, and every place is reachable without a pointer.

03God's Eye View architecture

About 177k tracked text lines, of which roughly 75k are bundled data (the CCTV ground-height table alone is 69,569). Vanilla ES modules, CesiumJS ^1.124, Vite 6, satellite.js, mgrs, egm96. A Node provider layer mounted as Vite middleware. 49 QA harnesses under scripts/qa-*.mjs.

How a layer lives

LayerLifecycle.register(module) takes a module exposing init / enable / disable / update / destroy / getStats. enable runs init and one immediate update(viewer, {signal}), then a setInterval at the module's refreshInterval. A refreshing flag prevents overlapping updates, refreshEpoch discards late completions, and intent epochs settle toggle races. disable keeps loaded data; destroy aborts fetches, discards late results and removes the layer's own context records. Failures are read from stats.error or stats.unavailable, so a layer can be enabled and unavailable at once.

How a request lives (the transit service, its most complete example)

The browser names a registered feed id, never a URL. Redirects are followed hop by hop, at most 3, and must stay on the same https origin. Limits: 15 s timeout, 8 MiB byte cap, 15 s TTL, 10-minute serve-stale window. Revalidation is conditional (ETag, Last-Modified), and a 304 restarts freshness. Refresh is single-flight. Admission is capped at 8 per feed and 40 globally per minute. Consecutive failures step through a 5 s / 15 s / 60 s / 300 s cooldown ladder that resets on success. Responses carry X-GEV-Cache: HIT | MISS | INFLIGHT | STALE-ERROR. The service keeps at (when the payload was fetched) separate from contactedAt (when the operator last answered). A shape error purges the cache and is never served stale.

Rendering and selection

  • Render governor. Cesium repaints every frame by default; GEV switches to request-render mode whenever no owner holds a continuous claim. Holds are an identity Set, not a counter, so a double release cannot corrupt the mode.
  • Label arbiter. One global screen-space solver: per-layer quotas, then placement through a spatial hash with incumbency, minimum lifetime, cooldown and fade (section 5).
  • LOD selectors per family. Budgets banded by camera height, a rank score, eviction grace, and motion-gated recompute.
  • Context store. A window-global registry of entity metadata keyed by id and owned by layer. Selection fires a CustomEvent.
  • Navigation generations. Each explicit navigation increments a counter; async results such as geocodes check it before moving the camera.
  • Share links. Hash parameters debounced 500 ms, allowlisted per style with clamped values, per-layer serialisation rules, and an at copy timestamp that rejects future or unsafe values.

What its own documents admit

docs/PERFORMANCE.md covers one M5 machine and three startup samples, and says outright it is "not a minimum hardware specification". KNOWN-ISSUES.md lists uneven traffic coverage under a global dot cap. The context store is mutable global state. Its candour about limits is itself worth borrowing.

05Algorithms worth borrowing, explained precisely

Each entry covers the mechanism, its cost, its failure modes and its fit. Where GEV leaves a constant unexplained, that is stated rather than guessed. n is candidates, k is placed items, c is grid cells touched per rectangle.

5.1 Label arbiter (src/data/labelArbiter.js) ◧ Reimplement

Problem
Many layers want screen-space labels at once. Naive greedy placement overlaps, starves some layers, and flickers as the camera moves because each frame's winner set is recomputed from nothing.
Algorithm
  1. Drop candidates with no key, no layer, or zero visibility (keyholeAlpha). Bucket the rest by layer.
  2. Sort each bucket by a total order: pinned (selected less than 2,500 ms ago) → incumbent (selected last solve) → priority → visibility → distance from screen centre → key.
  3. Split capacity across layers. Elastic: equal shares, with unused share redistributed. Weighted: weight = √count × semantic weight; one slot each first, then largest-remainder apportionment.
  4. For each layer, try incumbents first. They may take an overlap fallback so an established label is not ejected by a newcomer's rectangle. Then fill the rest from a farthest-point queue that spreads equal-priority labels apart.
  5. Each candidate offers up to four corner placements. The previous corner is tried first ("sticky"), and the first rectangle the spatial hash accepts wins.
  6. Labels that lost their slot enter fade-out (300 ms) and a cooldown until now + 300 + 1,200 ms, during which they cannot re-enter. State is garbage-collected after that.
Spatial hash
Uniform 32 px cells. Keys bit-pack (cx<<14)|cy into a small integer so V8 does not box doubles. Buckets are invalidated by a generation stamp rather than cleared. Collision is AABB with 4 px padding.
Inputs
{key, layerId, priority, keyholeAlpha, centerDistance, placements[≤4]{rect, corner}}, capacity, strategy, per-layer demand, now.
Outputs
Selected keys with placements; per-key state {selectedAt, enterStartedAt, exitStartedAt, cooldownUntil, corner}; diagnostics (quotas, retained incumbents).
Complexity
O(n log n) sort + O(n·c·b) placement, where b is the average bucket occupancy (small when cells ≈ label size). The farthest-point queue adds O(n·a) distance updates for a accepted anchors, bounded by capacity. Effectively linear per solve for bounded capacity.
Memory
O(n) state and typed-array scratch reused across solves; the stamp maps are pruned when they exceed the live cohort.
Failure modes
Labels that should change can be kept for up to 2.5 s. Cooldown can leave a gap where a label was. A stale incumbent may overlap via the fallback. Wall-clock time (Date.now) makes it hard to test without an injected clock, which GEV does pass in.
Why it exists
A 60 fps globe with thousands of moving candidates, where churn is the dominant visual defect.
Fit for LokDarpan
The stability ideas (incumbency, minimum lifetime, cooldown, fade, spatial hash, total-order tie-break) fit. The quota and semantic-weight ideas do not yet: there is one label layer, and a semantic weight would be an editorial hierarchy. The farthest-point spread is unnecessary for administrative units, which are already spatially distributed.
Changes needed
Neutral priority tuple (section 16). Anchors precomputed in PostGIS. An injected clock. Pin only the explicit selection, not "selected by the solver". Solve on move via rAF but re-sort only when the input set changes.

5.2 LOD active-set selection (src/data/localGeojsonLod.js) ◑ Adapt

Problem
At global zoom every feature is on screen at once, so per-feature geometry work explodes exactly when the features are least legible.
Algorithm
Budget by camera height: at least 3,000 km → 80; at least 200 km → 200; else 420. Unreadable height resolves to the cheapest band. Score = priority + 250 if incumbent − 200 × min(1, distance / 12,000 km). Duplicate ids collapse to the best score. Sort by score, then distance, then id; take the top budget. Priority comes from labelPriorityFromProperties: has a name +1000, English name +700, operator +180, output +120.
Constant design
The incumbent bonus (250) is deliberately smaller than the has-a-name gap (≥ 700), so incumbency reorders within a tier but never keeps an unnamed feature over a named one. The distance penalty (≤ 200) only breaks ties. This bounded-tier reasoning is the most transferable idea in the file.
Complexity / memory
O(n log n) per selection; O(n) maps.
Failure modes
A hard cutoff means feature n+1 is invisible with no signal; GEV relies on the overlay saying so. Priority from "has a name" systematically hides poorly tagged places.
Fit
Only once a point layer exists. The bias problem is disqualifying as written: in LokDarpan, "has a name" and "has an operator" correlate with how well a government publishes, so ranking by them would hide exactly the places where publication is weakest (the wireframe warns about this).
Changes needed
Aggregate instead of sample. Individual features only when the in-view count ≤ budget. Tie-breaks only on stable id. Truncation always announced (section 15).

5.3 Eviction grace (applyInfraEvictionGrace, from cctvLod) ◑ Adapt

Problem
A feature on the budget edge enters and leaves on every small camera move.
Algorithm
Newly selected ids enter immediately. A built id that falls out of the selection accumulates misses. It is evicted once misses ≥ 2 passes or 4,000 ms have passed since it first missed. Under cap pressure, graced ids are evicted first, oldest grace first, so the hard cap is never exceeded. The function is pure: it takes the previous grace map and returns a new one.
Complexity / memory
O(b log b) over built ids; O(b) grace map.
Failure modes
A feature can remain visible for up to 4 s after it should have gone. If a transient mode is not declared as such, a reader may read the grace period as data.
Fit
As zoom and count hysteresis between "aggregated by unit" and "individual records": enter individual mode at count ≤ 400, leave only at count > 480 or zoom out by more than 0.5. No time-based grace on data features.

5.4 Motion-gated recompute (shouldRecomputeInfraLod) ⊘ Do not use

Mechanism
Recompute at most every 1,000 ms, and only if squared travel since the last selection exceeds max(250 m, 2 % of camera height)². Travel is measured from the last selection, not the last probe, so slow drift still triggers eventually. An unreadable height takes the most eager epsilon, the opposite polarity to the budget, because a missed recompute empties the layer.
Why not
It compensates for Cesium follow and orbit cameras that emit no moveEnd. MapLibre emits move, moveend and zoomend for every camera change in LokDarpan, which has no autonomous camera. Two ideas are worth keeping as review guidance: scale-relative thresholds, and choosing the safe default per failure consequence.

5.5 Grid aggregation by band (FIRMS) ◑ Adapt

Algorithm
latCell = floor(lat / g) × g, same for longitude, with g = 2° above 9,000 km and 1° above 3,000 km. Each band has a cell cap (1,800 / 3,600). The aggregation is cached per grid size, invalidated per dataset, checked every 650 ms, and viewport-filtered via cellIntersectsBounds. Below 750 km: individual detections, capped at 2,500 / 3,000.
Complexity
O(n) per grid size, once per dataset; O(cells) per view.
Failure modes
Grid cells are arbitrary and cut across administrative units; equal-degree cells vary in area by latitude.
Fit
The idea (precomputed aggregates per band, cached per data version, individual records only when zoomed in) is exactly right. The grid is wrong for LokDarpan: aggregate by admin_unit, which is a cited place with a name and a canonical URL, and compute it in PostGIS keyed by datasetVersion, never in the browser.

5.6 Capped body read (src/sources/httpBody.js) ◧ Reimplement

Algorithm
If Content-Length exceeds the cap, cancel the body and throw RESPONSE_TOO_LARGE. Otherwise read the stream chunk by chunk, adding byteLength to a running total; past the cap, cancel the reader and throw. Honour an AbortSignal between reads. The bytes variant buffers the chunks and concatenates once at the end.
Complexity / memory
O(bytes) time. Peak memory = cap (bytes variant) or roughly 2 × cap (text: chunks plus UTF-16 string).
Subtlety GEV does not handle
Node's fetch (undici) transparently decompresses gzip and br. Content-Length is the compressed size while the stream yields decoded bytes. The early check therefore under-rejects, but the streaming count on decoded bytes is what actually defends against a decompression bomb. LokDarpan must rely on the decoded count, and should send accept-encoding: identity for PDFs, which are already compressed.
Failure modes
A slow trickle stays under the cap forever unless there is an idle timeout. Buffering a 150 MB PDF in memory is legal under a 200 MB cap but wasteful. LokDarpan should stream to disk while hashing.

5.7 Single-flight coalescing (coalesceProxyRequest) ◑ Adapt

Algorithm
inFlight.get(key) returns {promise, shared:true} if present. Otherwise it creates Promise.resolve().then(create).finally(...) and, on settle, deletes the key only if the map still holds this exact promise, so a newer request for the same key is not evicted by an older one settling.
Complexity
O(1); memory O(in-flight keys).
Failure modes
No cancellation: if one caller aborts, the shared upstream continues, correct only because the proxy serves many callers. A rejection is shared by all waiters, which is correct. There is no result cache; that is a separate TTL layer.
Fit
See section 19 for where it belongs; the key must include datasetVersion.

5.8 Cache state and cooldown machine (transit service) ◑ Adapt

States
none → fresh (age < 15 s) → stale (< 10 min) → expired. Negative age counts as fresh (clock skew).
Transitions
Fresh: serve. Otherwise, if cooling down or not admitted: serve stale with STALE-ERROR if one is held, else 503 with Retry-After. Otherwise coalesced refresh: 304 → restart at and contactedAt; 200 → capped decode → replace; failure → failures += 1, next attempt after ladder[min(failures, 4) − 1], then serve stale or 502/504. A shape fault purges and returns 502 without serving stale.
Key insight
Three independent timestamps answer three questions: when the payload was produced, when the operator last answered, and when we may ask again. Conflating them either makes a dead feed look alive or ages a healthy feed into silence. LokDarpan's tender status already separates last_success_at from last_checked_at; section 17 generalises it.
Fit
The timings are real-time and irrelevant. The state separation and the "a shape fault is not an outage" rule transfer directly to ingestion: a portal that changes its HTML is a parser failure, not "stale data".

5.9 Supersession guards (navigation generations, refreshEpoch, sourceSlot) ■ Borrow

Algorithm
A monotonically increasing counter is captured when async work starts and compared when it ends; mismatched results are dropped. createSourceSlot rejects a result as AbortError if its provider was replaced while the call was pending.
Complexity
O(1).
Fit
LokDarpan's AbortController per effect already covers most of this. The one new guard needed: version supersession. A response whose meta.datasetVersion differs from the view's pinned version must be discarded and refetched, never merged.

5.10 Sliding-window admission limiter (src/sources/rateLimit.js) ⊘ Do not use

Algorithm
Per key, an array of timestamps filtered to the window, plus a global array for a backstop. The map is capped at 2,000 keys, evicting the oldest insertion.
Complexity
O(hits in window) per call, both per key and globally; O(keys × max) memory.
Why not
It is in-process, so a serverless deployment with many isolates enforces nothing globally. It is keyed on socket address, which on Indian carrier-grade NAT puts thousands of readers behind one IP. Correct for GEV's localhost proxy; wrong for a public civic site. For outbound politeness toward government hosts, a sequential per-host queue with a minimum interval is simpler and already how the collectors behave.

5.11 Motion interpolation and dead reckoning (flights/motion.js, motionModel.js) ⊘ Do not use

Mechanism
Render one interval behind real time, interpolate between fixes, dead-reckon along course and speed when fixes stop, cap course slew in degrees per second, ease floor heights.
Why not
It invents intermediate positions, which is acceptable for a moving aircraft on a visual globe and unacceptable for a ledger. Nothing in LokDarpan moves; animating a figure between two published values would display numbers no source published.

Lifecycle, via one binder

Algorithm: aggregate first, sample never

  1. Server answers counts first. A records request for a viewport returns {total, byUnit[]} from PostGIS (&& on GIST, grouped by the smallest admin level with a boundary at that zoom).
  2. Mode decision with hysteresis: individual when total ≤ B(zoom); switch back to aggregate only when total > 1.2 × B or zoom drops by 0.5 below the entry zoom. This prevents flapping at the edge, the same purpose as GEV's grace window, but keyed to data and camera rather than wall time.
  3. Aggregate mode draws unit shading or unit-anchored count markers ("312 records"), each clickable to zoom in. Nothing is hidden: every record is inside some count.
  4. Individual mode fetches features with limit = B; the server guarantees total ≤ B, so no subset is chosen.
  5. Unmapped records (no published location) are counted separately and announced ("18 records here have no published location and are not on the map").
  6. Selection pin. A selected feature is always drawn, even in aggregate mode, as a single overlay. This is the only incumbency rule.

Choosing B

Do not copy 400 or GEV's 80/200/420. Measure: render p95 frame time and hit-test latency on the reference mid-tier Android profile at 250, 500, 1,000, 2,000 features, then take the largest count keeping pan p95 ≤ 33 ms and tap-to-drawer ≤ 150 ms. The wireframe's 400 is a reasonable starting hypothesis to test, not a constant to ship.

If sampling were ever unavoidable

For example, a label or icon collision among features with identical positions: choose by hash(id), stable across sessions and versions, never by an attribute. And say that it happened.

16Proposed label arbitration model

Keep DOM labels; do not switch to a symbol layer (verify first)

A MapLibre symbol layer would give collision, fades and symbol-sort-key for free, once glyph PBFs are self-hosted. The blocking concern is script shaping. To the best of my knowledge, MapLibre GL JS does not perform complex text shaping for Indic scripts, so Devanagari, Tamil or Bengali conjuncts would render incorrectly, while DOM text uses the browser's shaper. LokDarpan already handles Tamil in its OCR pipeline (migration 0021) and will want local-script names. Verify against the pinned v5 before deciding; if shaping is supported, prefer the symbol layer and skip the rest of this section.

Neutral priority, as a lexicographic tuple

  1. Explicitly selected unit (always placed)
  2. Keyboard-focused or hovered unit
  3. Ancestors of the selection shown on screen (orientation)
  4. Administrative level rank: coarser before finer
  5. floor(log2(area_m2)), computed in PostGIS on geography, not degrees². Bucketed so small area differences do not decide.
  6. Stable id

Excluded: population, spend, tender counts, observation counts, political boundaries of constituencies, "has a local name". Area is geometric, not a judgement; it is already the current tiebreaker, just measured wrongly.

Mechanism

  • Anchor from PostGIS (label_point), not the bbox midpoint.
  • Measure once, in a batch. Create all nodes in a DocumentFragment, attach, then read widths in one pass (one layout instead of n).
  • Sort only when the candidate set changes; incumbency is applied as a pre-partition (incumbents first, in priority order), which needs no re-sort.
  • Grid: cell = 2 × median label height (≈ 32 px at 12 px type). Map<number, Rect[]> with generation stamps.
  • Hysteresis during camera motion only: a placed label is kept if still on screen and colliding only with lower-priority labels; minimum on-screen time 600 ms; cooldown 400 ms before a removed label may return. Shorter than GEV's 2.5 s / 1.2 s because nothing moves on its own, and a reader panning a state wants responsive names.
  • Fade: opacity transition 120 ms in, 180 ms out; disabled under prefers-reduced-motion.
  • Budget: at most 150 live nodes; beyond that, do not create markers for off-screen candidates (create on entry, remove after cooldown).
  • Write only on change: toggle opacity or visibility only when the state flips.
  • Clock injected so the tests are deterministic.

GEV's discipline is a table in a Markdown file and an attribution line in the app. LokDarpan's bar is higher: the map must answer "where did this come from?" from the payload itself.

How it travels

  • Payload meta.sources: SourceDescriptor[], deduplicated; each feature carries only properties.src: number[] (indices), which keeps GeoJSON small.

  • publishable.ts's environment gate becomes licence.displayPermitted, still false for BEAMS until permission exists.

Choosing numbers instead of inventing them

  1. Byte caps: run once against the raw store: SELECT source_id, max(byte_size), percentile_cont(0.99) WITHIN GROUP (ORDER BY byte_size) FROM source_artifact GROUP BY source_id;. Set cap = max(4 × observed max, the largest size the publisher documents), rounded up to a power of two. Record the query output in the ADR. Until measured, fail open to a generous ceiling per content type (listing HTML: 16 MiB; PDFs: 512 MiB streamed to disk; Overpass JSON: 256 MiB) and log every response above 25% of it.
  2. Timeouts: headers 30 s (government hosts are slow, not silent); idle 60 s (resets per chunk, which is what kills a trickle); total = max(10 min, cap / 50 KiB/s floor). Revisit from logged elapsedMs p99 × 3 after two weeks.
  3. Retries: 3 attempts per URL; ladder 30 s → 2 min → 10 min with ±20% jitter; per-host circuit: 5 consecutive failures stop further requests to that host for the run and record the note. This is GEV's ladder at batch timescale and prevents a retry storm against one portal.
  4. Concurrency: 1 per host (existing behaviour, now enforced), independent hosts may run in parallel.
  • Decompression: send accept-encoding: identity for binary artifacts; for HTML allow gzip but count decoded bytes. Never unzip archives in memory; stream-extract with a per-entry and total cap.
  • Parsing: JSON and CSV parsers get the same cap as the fetch; CSV row count capped per source.
  • Partial responses: there are none. A body that did not complete is a failed fetch; it is never stored, hashed into the raw store or parsed.
  • Logging and metrics: one structured event per fetch {sourceId, host, status, bytes, elapsedMs, class, attempt, sha256}, secrets scrubbed via @lokdarpan/observability's scrubSecrets; histograms via the existing BYTE_BUCKETS and LATENCY_BUCKETS; error class rolled up into ingestion_run.note.

Borderline ideas, evaluated separately

Geocoding village and town names

Verdict: do not geocode for display. Nominatim's usage policy forbids bulk and systematic use; Photon's public instance is fair-use only. Indian village names repeat many times within a state and transliterate inconsistently, so a text match is frequently a different village, and a wrong point looks as authoritative as a right one. Acceptable internal uses: matching records to admin_unit by LGD code, and pincode-to-office joins, each stored with placement.method and linkage confidence, rendered as unit shading, never pins. Official gazetteers (Survey of India, Bhuvan village layers, any data.gov.in coordinate sets) must be verified for existence, licence and terms through the registry process before use; none is assumed here.

Satellite imagery to check construction

Verdict: a separate research capability, not a map layer. Sentinel-2's 10 m pixels cannot reliably resolve a 3–5 m rural road or its surface; higher resolution is commercial or restricted. More fundamentally, "the imagery shows no road" is an analyst's inference, which LokDarpan's rules treat as categorically different from a published record, and the image date rarely matches the claimed completion date. If ever pursued: imagery as dated, licensed reference context beside the record, with no automated built or not-built judgement.

Guided map tours

Verdict: defer; if built, template-only. GEV's Director is a well-engineered scene document (versioned, validated, cancellable). A scripted money-trail tour, though, chooses order, emphasis and pacing, which is editorial. The acceptable form is a generated walkthrough of records a source links, in publication-date order, each step rendered through the same provenance components, with no narration beyond vetted templates and missing stages shown as missing.
